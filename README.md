# NovelAI Prompt Autocomplete

> **公告**：作者正在集中维护提示词 skill，欢迎在 <https://github.com/Miint-Sunny/nai5-prompting> 反馈。

基于 Chrome Manifest V3 的 NovelAI 浏览器扩展，包含以下功能：

- NovelAI tag 自动补全
- 基于大语言模型（LLM）的图片反推
- 按 skill 生成提示词的写词助手（提示词 Agent）
- tag 流编辑器（改词）
- 画师记录本：管理画师和画师串

项目仓库：<https://github.com/Miint-Sunny/nai-autocomplete>（fork 自 <https://github.com/saltysalrua/nai-autocomplete>）

## 功能概览

### 1. NovelAI tag 自动补全

在 `https://novelai.net/*` 页面的提示词输入框中提供 tag 补全：

- 按 Danbooru 风格搜索 tag，显示常用 tag 候选
- tag 数据缓存在本地
- 可切换下划线与空格
- 可按分类给每个 tag 加下划线（画师、角色、场景等；词典未收录的 tag 显示为红色虚线）。默认关闭，可在补全弹窗顶部开启
- 支持把提示词分组为区块，并锁定、拖动排序
- 可以把区块保存为词库条目，之后用 `char:xxx`、`style:xxx` 等写法复用
- `char:` 条目可以设置**别名**（中文名、原名、昵称）；写词时，画面描述中出现任一别名，就会使用该角色

### 2. 图片反推

在任意网页中打开悬浮窗，选择图片后调用大语言模型反推提示词，并自动复制结果。

- **直接读取 NovelAI 原图中的提示词**：支持 PNG 文本块和 alpha 通道。读取成功时不调用模型、不上传图片、内容逐字准确；读取失败时自动改用模型反推
- 按住 `Alt + Shift` 点击图片，即可选中图片并打开悬浮窗
- 可以在网页中手动选择图片（「从网页选图」）
- **打开本地图片**：反推页的「打开本地图片」会记住上次使用的文件夹；本地的 NovelAI 原图同样可以直接读取提示词，不产生费用
- 兼容 Pixiv 等带遮罩层的页面
- 图片直链无法读取时，自动改用抓取或截图
- 悬浮窗可以拖动和缩放；右下角的悬浮按钮也可以拖动，位置会被记住
- **两个入口分别打开两个界面**：悬浮按钮打开悬浮窗；浏览器工具栏中的扩展图标在 NovelAI 出图页打开工作台，在其他网站打开悬浮窗
- 保存反推历史记录
- 写词时，如果本地词典未收录某个 tag，会向 Danbooru 实时查询一次（含别名解析），只发送 tag 名称；已打开 Danbooru 标签页时优先使用其登录状态。可以在设置中关闭
- 支持角色替换：选择内置的「角色替换」预设，反推时把图中人物换成目标角色
- **一键填入角色栏**：写词生成的角色提示词可以直接填入 NovelAI 的角色栏（Character 1～6）；角色栏不够时，会自动点击 NovelAI 的「Add Character」按钮（只填写输入框，不会点击「Generate」）
- 可以设置默认以代码块输出，也可以手动把结果转为代码块
- 可以隐藏悬浮按钮，只通过快捷键或扩展图标打开悬浮窗
- 在 NovelAI 以外的网站，默认**不显示**悬浮按钮，可以点击扩展图标打开悬浮窗（可在设置中重新开启）
- 内置 10 套配色，包括 **流光玻璃 · 浅 / 深**（Apple 系统配色和 Liquid Glass 材质）
- 毛玻璃效果可以开关，强度可用滑块无级调节（0% 为不透明，100% 为全透明玻璃）

### 3. 写词助手（提示词 Agent）

根据一份**可替换的 skill**，把中文画面描述写成 NovelAI 提示词。界面是一段**对话**：发送描述、收到回复，再在回复的基础上继续修改。悬浮窗和工作台的「写词」页都可以使用。

- 内置 nai5-prompting（NovelAI V5 提示词指南），安装后即可使用
- skill 可以导入、编辑、导出和切换；内置 skill 为只读，始终保留
- **统一的导入框**：选择文件或直接粘贴内容后，先显示在可编辑的文本框中，并预览解析结果，确认后再导入。skill 和 SillyTavern 预设使用同一个导入组件
- **两种提示词格式**（设置 → 提示词 → 提示词格式）：**NovelAI V5** 混合使用 Danbooru tag 和自然语言；**NovelAI V4.5** 以经过查证的 Danbooru tag 为主。切换后，生成方式的说明、附加的官方规则和内置反推预设会随之切换
- tag 查证使用本地 Danbooru 词典：先用中文释义预先查出一批确定存在的 tag，模型不确定时再调用 `search_tags` 补充查询
- **四种生成方式**：默认、展开（多人时分角色栏）、改写（整理现有提示词）、精简（优先使用准确的 tag）。V5 和 V4.5 各有一套说明
- **角色栏数量**可以指定为 0～6；指定后，模型会输出相同数量的角色栏
- 自动附加对应版本的**官方规则**（V5：权重语法、两种透明、画面文字、`depthness` 等新 tag；V4.5：以 tag 为主、角色栏最多 6 个）。使用自定义 skill 时同样生效，可以在设置中关闭
- **按名称使用角色**：画面描述中写到词库角色的名称或别名，就会使用该角色已有的外观描述，并分配到对应的角色栏
- **结果不会自动填入**：回复中的每个提示词块都有「填入」「追加」「改词」「复制」按钮，角色块可一键填入角色栏。对话保存在本地，点击「清空」开始新对话
- **只生成提示词，不会触发出图**

详见 [AGENT.md](./AGENT.md)。

### 4. tag 流编辑器（改词）

把提示词拆成可拖动、可加权、可编辑的 tag 块。悬浮窗和工作台的「改词」页都可以使用。

- 识别 NovelAI 提示词的三层结构：`|` 分段（多角色时按段分页签）、换行分层、逗号分隔的条目（包括 `1.2::a, b::` 权重组）
- 自然语言句子作为一个整体，不会被逗号拆开
- 识别三种权重写法（`{x}`、`[x]`、`(x:1.2)`），输出时统一转为 NovelAI 的数值权重语法
- 两层分类着色：左侧竖条表示 Danbooru 来源（画师、角色、版权、元信息），底色表示语义分类（主体、外貌、服饰、动作、表情、场景、光影、构图、质量）
- **标出词典未收录的 tag**
- 左键拖动排序，按住右键上下拖动调整权重，点击编辑（带补全），支持多选批量操作、撤销和重做
- 反推结果和写词结果都可以一键「发送到改词」，也可以直接读取或写回网页中的输入框

详见 [FLOW.md](./FLOW.md)。

### 5. 画师记录本

独立的扩展页面，用于记录画师和画师串（打开方式：悬浮窗 →「画师」→「管理」）。

- 可以建立多个画师库，每个画师库独立保存画师、分类、评分、图片和画师串
- 画师信息：画师 tag、出图总评（5 颗星，可打半星，按 10 分制显示，如 `9/10`）、分类、笔记、作品缩略图
- 对比记录：画师原图和 NAI 生成图并排对比，附提示词和相似度。可以在卡片上直接点击星星评分（半颗星为 1 分，满分 10 分；再次点击当前分数可清除），也可以随时点击「编辑」更换图片、修改提示词、相似度和备注
- 画师串收藏：关联的 PNG 原图按原始文件保存，并自动读取其中的提示词、Seed、模型、Steps 和 CFG
- 从 Danbooru 获取画师原图：支持单个画师和批量获取，可以随时停止；遇到 403 时会保存作品信息
- 支持导出和导入备份、单独导出和导入画师串，以及导出离线手机版网页（包含画师、画师串和词库三个页签，发送到手机即可搜索和复制）
- 分类由画师和画师串共用，支持多个分类组合筛选
- 显示存储占用和原图统计

悬浮窗的「画师」页和工作台的「画师库」页也可以搜索画师，并按分类和评分筛选；点击卡片或「＋」把画师 tag 或画师串追加到当前提示词框，点击「📋」只复制。

### 6. 多模型与多服务商

设置页可以分别配置主模型和备用模型。

推荐使用 **OpenAI 兼容协议**和**支持图片输入的 flash 级模型**，各服务商的默认模型也按此设置。

- 主模型请求失败时，自动改用备用模型
- 自动获取模型列表
- 测试连接
- 内置常用服务商的接口协议、API 地址和默认模型
- **API 地址只需填写到域名**：与各家 SDK 和 SillyTavern 的做法一致，按接口协议自动补全 `/chat/completions`、`/v1/messages` 等路径，补全后的完整地址显示在输入框下方

内置的服务商：

- OpenAI
- OpenRouter
- xAI (Chat Completions)
- xAI (Responses API)
- Google Gemini（OpenAI 兼容）
- Google Vertex AI（OpenAI 兼容）
- DeepSeek
- Anthropic
- 自定义

支持的接口协议：

- OpenAI Chat Completions
- Responses API
- Anthropic Messages API

## 安装

### 从 Release 安装（推荐）

1. 在 <https://github.com/Miint-Sunny/nai-autocomplete/releases> 下载 `nai-autocomplete-vX.Y.Z.zip`。
2. **解压到一个固定的文件夹**，之后不要删除或移动它。扩展是从这个文件夹加载的，加载后仍需保留。
3. 在 Chrome 或 Edge 中打开 `chrome://extensions`，打开右上角的「开发者模式」。
4. 点击「加载已解压的扩展程序」，选择解压得到的 `nai-autocomplete` 文件夹。

首次在 novelai.net 使用时，扩展会自动下载 Danbooru tag 词典并缓存到本地，**这一步需要能够访问 GitHub**。自动补全、写词的 tag 查证和改词的分类着色都依赖这份词典。

> **如需修改扩展的行为（例如调高某个上限）**：Release 包中只有 `js/bundle/*.js` 等**构建产物**，不包含 `js/` 下的源码分片。直接修改 bundle 只对当前文件夹有效，**更新扩展后会被覆盖**，且不会有任何提示。如需长期生效，请按下方「从源码构建」修改源码分片。

### 从源码构建

仓库中**不包含**构建产物（`js/bundle/` 和 `styles/bundle.css` 已加入 .gitignore），克隆后直接加载会失败，需要先构建：

```bash
git clone https://github.com/Miint-Sunny/nai-autocomplete.git
cd nai-autocomplete
node scripts/build-modular.mjs
```

然后按上方第 3、4 步加载仓库根目录。如需检查发布包是否完整：

```bash
node scripts/package.mjs --zip
```

## 使用说明

### 自动补全

1. 打开 NovelAI 出图页。
2. 在提示词输入框中输入 tag。
3. 从候选列表中选择 tag 完成补全。
4. 选中多个 tag 后可以创建区块，并直接拖动排序。
5. 把区块保存到词库后，输入 `yuukarin` 或 `char:yuukarin` 即可补全整个区块。

### 图片反推

1. 打开包含图片的网页。
2. 用以下任一方式选择图片：
   - 按住 `Alt + Shift` 点击图片。
   - 点击右下角的悬浮按钮（或浏览器工具栏中的扩展图标）打开悬浮窗，再点击「从网页选图」。
   - 点击「打开本地图片」，选择电脑中的图片（会记住上次使用的文件夹）。
3. 在设置页填写模型服务的配置。
4. 点击「反推并复制」。
5. 反推结果会显示在悬浮窗中，并自动复制到剪贴板。
6. 如需替换图中人物，请在设置页选择「角色替换」预设，并填写目标角色提示词；也可以在「词库角色」中选择 `char:` 条目，点击「应用到目标角色提示词」。

### 写词（提示词 Agent）

1. 在悬浮窗中切换到「写词」页。
2. 选择「生成方式」（默认、展开、改写或精简）；需要固定人数时，在「角色栏」中选择数量。
3. 在底部输入框中用中文描述想要的画面，点击「发送」。**描述中写到词库角色的名称或别名，就会使用这个角色**；请同时在知识源中勾选「词库角色」。
4. 继续在回复的基础上提出修改要求即可迭代：对话记录会自动附带，模型只修改需要修改的部分，并说明改了什么。如需以**输入框中的现有内容**为基础修改，请勾选「当前提示词」（切换到「改写」时会自动勾选）。
5. 用提示词块上的「填入」「追加」「复制」把结果写入输入框，或点击「改词」发送到 tag 流编辑器；多角色时，点击「全部填入」可一次填好主提示词和所有角色栏。点击「清空」开始新对话。

### 改词（tag 流编辑器）

1. 在悬浮窗中切换到「改词」页，点击「读取输入框」导入当前提示词（也可以从反推页或写词页发送过来）。
2. 每个 tag 显示为一个块，颜色表示它的分类；**红色虚线边框表示词典未收录**。
3. 左键拖动排序，按住右键上下拖动（或滚动滚轮）调整权重，点击 tag 进行编辑，按住 Ctrl 点击可以多选。
4. 多角色提示词会按 `|` 分为「主提示词」「角色 1」「角色 2」等页签，把 tag 拖到其他页签即可移到对应角色。
5. 修改完成后，点击「写入输入框」。

### 设置项

| 分组 | 设置项 |
|---|---|
| 模型服务 | 服务商、接口协议、API 地址（含「自动补全 API 路径」开关）、模型、API Key（点击 ⓘ 查看获取方法）、获取模型列表、测试连接 |
| 备用模型 | 启用备用模型；独立的服务商、接口协议、API 地址、模型、API Key 和思考强度，主模型请求失败时自动改用 |
| 生成参数 | 温度、Max Tokens、思考强度 |
| 发送与输出 | 优先读取 NovelAI 原图中的提示词、本地词典未收录时查询 Danbooru、写词时附加官方规则、发送图片数据、附加图站 tag、默认以代码块输出 |
| 提示词 | 提示词格式、预设（系统提示词和反推指令）、目标角色提示词（使用「角色替换」预设时显示，可从词库角色套用）、导入 SillyTavern 预设 |
| 外观 | 配色（10 套，包括流光玻璃浅 / 深）、悬浮按钮的显示范围（三个开关）、毛玻璃效果和强度 |

关于「自动补全 API 路径」：开启后，API 地址只需填写到域名（如 `https://api.deepseek.com`），扩展会按接口协议补全路径，并在输入框下方显示完整地址。使用自建网关且路径特殊时，请关闭此项并填写完整地址。

## 推荐的使用流程

1. 在设置页选择服务商。
2. 填写 API Key。
3. 点击「获取模型列表」，选择要使用的模型。
4. 点击「测试连接」，确认主模型和备用模型的配置有效。
5. 开始使用图片反推或写词。

### 使用真实 API Key 测试

`.env` 已加入 `.gitignore`（仓库是公开的，请勿删除相关规则）：

```bash
cp .env.example .env              # 填写 NAI_API_KEY
node scripts/check-provider.mjs            # 不带参数：列出可选的服务商
node scripts/check-provider.mjs deepseek   # 使用指定的服务商测试
```

脚本运行的是 `js/background/` 中实际发布的代码，只把 fetch 换成真实的网络请求：先获取一次模型列表，打印将要发送的请求体结构，再进行一次真实的写词请求（带工具调用）。服务商和 API 地址取自扩展自身的 `PROVIDER_PRESETS`，不在脚本中重复定义。输出中的 Key 会被遮挡，可以直接贴到 issue 中。**此脚本不在 CI 中运行**，只用于本地手动测试。

**修改模型协议层之前，请先用它测试一遍**：协议层是否正确只有真实的服务端能判断。单元测试只能保证「发送的请求结构符合预期」，无法保证「服务端接受这个结构」。

修改后请运行以下命令（与 CI 一致）：

```bash
node scripts/check-theme-tokens.mjs   # 主题变量完整性与 CSS 变量自引用
node scripts/test-llm.mjs             # 模型服务
```

测试使用 `node:vm` 加载**实际发布的分片**，而不是为测试另写的副本。修改样式后，除了运行脚本，还必须实际渲染并截图检查（见 [STYLE.md](./STYLE.md) 第 9 节）。

### 为什么需要构建

Chrome 的 content script **不能**让多个独立的 `.js` 文件共享同一个 IIFE 作用域中的 `const` / `let`。因此源码按分片维护，运行前由构建脚本把分片**合并为单个 bundle**。

构建只做拼接，不做任何转换（由 `scripts/test-build.mjs` 检查）。

## 已知限制

- 图片反推依赖你自行配置的模型服务，扩展不内置 API Key。
- 部分网站会对图片直链做防盗链限制。扩展内置了备用的读取方式，但仍可能受网站策略影响。
- 不同服务商支持的模型、接口协议和图片输入能力不完全相同。
- 首次使用需要访问 GitHub 下载 tag 词典；无法下载时，自动补全和 tag 查证会受影响，其他功能不受影响。
- 发送给模型的图片会先压缩到 1536px、1.4 MB 以内，较大的原图会被等比缩小。
- **不提供任何自动出图或批量出图功能**，扩展只用于编写和修改提示词。
